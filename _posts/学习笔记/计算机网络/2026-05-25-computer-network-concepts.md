### 各种号

1.IP地址 32位 每个设备

2.MAC地址 48位 物理地址

+ 00-1A-2B-3C-4D-5E`，前 24 位是厂商代码，后 24 位是设备序号
+ **作用**：在同一局域网（如 Wi-Fi）内直接通信时用

3.自治系统号（AS 号，16 位）
是什么：互联网被分成很多“自治系统”，每个系统有一个编号

16 位：范围 1~65535，如中国电信有一个 AS 号

作用：BGP 路由协议用 AS 号来标识不同网络运营商或大型网络

4.端口号（16 位）

是什么：用于区分同一设备上的不同应用

16 位：范围 0~65535，如 HTTP 用 80 端口，HTTPS 用 443 端口

作用：让同一台设备能同时运行多个网络程序

示例：

你同时打开网页和微信 → 电脑用不同端口与服务器通信

192.168.1.1:8080 表示 IP 为 192.168.1.1 的设备上的 8080 端口服务

**1. 从底层到高层**

**IP（网络层）**

+ **作用**：负责把数据包从源设备送到目的设备
+ **特点**：无连接、不可靠、只认 IP 地址
+ **比喻**：**快递运输系统**——只关心把包裹从 A 市送到 B 市，不保证不丢、不坏、不延迟

------

**TCP vs UDP（传输层）**

| 协议    | 特点                         | 比喻                                                        |
| :------ | :--------------------------- | :---------------------------------------------------------- |
| **TCP** | 可靠、有连接、有序、流量控制 | **挂号信+电话确认**：确保对方收到，没收到就重发，按顺序整理 |
| **UDP** | 不可靠、无连接、简单快速     | **普通明信片**：扔进邮筒就不管了，可能丢失，但投递快        |

**常见用途**：

+ TCP：网页（HTTP）、电子邮件、文件传输
+ UDP：视频流、语音通话、DNS 查询、游戏数据包

------

**HTTP（应用层）**

+ **作用**：客户端和服务器之间传输网页内容的规则
+ **特点**：基于 TCP，无状态（每次请求独立）
+ **比喻**：**书店购书流程**——你说“我要《三体》”，书店给你书，交易完成
+ **常见**：网址开头的 `http://` 或 `https://`

------

**DNS（应用层）**

+ **作用**：把域名（如 `www.baidu.com`）转换成 IP 地址（如 `39.156.66.10`）
+ **特点**：通常用 UDP 查询（快），也可用 TCP
+ **比喻**：**电话簿**——查“北京饭店”的电话号码
+ **过程**：你在浏览器输入网址 → 电脑问 DNS 服务器“这个网址的 IP 是多少？” → 得到 IP → 用 IP 访问网站

------

**2. 完整流程示例（访问网站）**

1. **DNS 查询**：浏览器问 DNS 服务器“`www.example.com` 的 IP 是多少？”（UDP）
2. **TCP 连接**：浏览器和服务器建立 TCP 连接（三次握手）
3. **HTTP 请求**：浏览器通过 TCP 发送 HTTP 请求“请给我首页”
4. **IP 路由**：TCP 数据包被 IP 协议封装，通过网络路由到服务器
5. **HTTP 响应**：服务器通过 TCP 发回网页内容
6. **TCP 断开**：传输完成后断开连接（四次挥手）

3. **各层分工总结**
    层	协议	关心的问题
    应用层	HTTP、DNS	传什么（网页内容、域名解析）
    传输层	TCP、UDP	怎么传（可靠还是快速）
    网络层	IP	往哪传（IP 地址路由）

4. **一句话记忆**

  DNS：域名→IP 地址的翻译官

HTTP：网页内容的快递员

TCP：可靠送货的保镖

UDP：只管扔的快递小哥

IP：只认地址的卡车司机

**附：各层核心功能简述**

1. **应用层**：为用户应用提供网络服务接口（如浏览器访问网页）。
2. **运输层**：提供端到端的可靠或不可靠传输，复用和分用。
3. **网络层**：跨网络寻址和路由选择，使数据包能到达目标网络。
4. **数据链路层**：在相邻节点间无差错传输帧，进行流量控制和差错检测。
5. **物理层**：在物理介质上透明传输原始比特流。

### 数据链路层

两种信道：点对点信道（一对一） 广播信道（一对多）局域网 都能收到

#### 点对点协议PPP

PPP（Point-to-Point Protocol，点对点协议）是数据链路层协议，用于在两个节点之间直接通信。

PPP 的功能：
**封装成帧**：加首部尾部 把网络层数据包装成 PPP 帧

MTU数据部分上限

！**透明传输**：解决数据部分出现帧定界符

用字节填充或零比特填充防止数据中出现 0x7E

透明传输 指 数据链路层 对上层交付的数据**不做任何改变**、不识别内容，原样传输，就好像链路层“透明”一样

因为数据中可能包含与帧定界符相同的比特模式，如果不处理，接收方会**误判帧的边界**

1.**字节填充（异步传输**用）

数据中出现 **0x7E → 转义为 0x7D 0x5E**

数据中出现 **0x7D → 转义为 0x7D 0x5D**

出现ASCII码（小于0×20 eg:0×03) 前加0×7D （**0×7D ，0×03**）

接收方反向转换

效果**：数据中永远不会出现 0x7E，帧定界符唯一**

2.**零比特填充（同步传输用）**

数据中每出现 连续 5 个 1，后面插入 1 个 0

接收方每收到连续 5 个 1 后面的 0 就删掉

效果：**数据中永远不会出现 6 个连续的 1，而标志 01111110 中有 6 个 1，所以不会被误判**

**差错检测**：CRC 校验

#### 解决碰撞协议CSMA/CD

多点接入：总线型 多计算机接在一根线上

载波监听：**先听后发**

碰撞检测：**边听边发** 检测到碰撞：立即**停止发送+发干扰信号+根据退避算法（随机时间取争用期2r）等一段时间再发**

在发了之后2r(争用期/碰撞窗口：往返时延)后，就可以知道有没有碰撞
